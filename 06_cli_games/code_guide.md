# コードの書き方

サンプルのゲームは、読みやすさを優先して次の決まりで書きます。

## 共通

- はじめてゲームを作る人が読みやすいよう、できるだけシンプルに書く。ゲームに関係のない演出は入れない
- Python 版と JavaScript 版は**同じ形**にする。区切り・関数分け・関数の並び・コメントをそろえ、片方だけ読んでももう片方と行き来できるようにする
- ファイルは「定数 → 状態の切り替え → 更新 → 描画 → メイン処理」の区切りで並べる。呼ばれる小さな関数を先に、呼び分ける関数（`update()` / `draw()`）をその後に置く
- 関数の中は、ひとまとまりごとに 1 行のコメント（`# 入力の判定: ...` など）を付ける
- 定数には、何の値かを 1 行のコメントで書く
- ゲームの状態は 3 本とも `GAME_STATE_XXX` の文字列の定数で表す（1 本目は変数 `game_state`、2・3 本目は `Game` の `game_state`）
- ゲーム全体のデータは `Game` クラスにまとめ、辞書に詰め込まない
- bool の変数・フィールドは `is_xxx`（JavaScript は `isXxx`）の名前にする（`is_running`、`is_alive`）
- **入力・更新・描画を分ける**。入力の関数は値を返すだけ、状態を変えるのは更新の関数だけ、描画の関数は状態を変えずに表示だけをする
- 更新は `update_xxx()`、描画は `draw_xxx()` に名前をそろえる
- 画面に出すキーの名前は、打つ文字と同じ小文字で書く（`r: タイトルへ / q: 終了`）

## Python 版

- ファイル名・関数名・変数名はスネークケース。ゲームの起点は各フォルダの `python/main.py`
- 関数・クラスには日本語の Google 形式 docstring を付ける（引数は `Args:`、戻り値は `Returns:`、クラスのフィールドは `Attributes:`）
- docstring にも型を書く。引数とフィールドは `game (Game): 説明`、戻り値は `str: 説明` の形で、型注釈と同じ型にする
- 関数の引数・戻り値と、意味を持つ変数には型注釈を付ける

## JavaScript 版

- 関数名・変数名はキャメルケース（`updatePlaying()`）、定数は Python 版と同じ大文字（`GAME_STATE_TITLE`）。ゲームの起点は各フォルダの `javascript/main.js`
- 関数・クラスには日本語の JSDoc を付ける（引数は `@param`、戻り値は `@returns`、クラスのフィールドはそれぞれの上に 1 行）
- 待つ処理（入力・フレームの待ち）は `await` で書き、`main()` を `async` にする
